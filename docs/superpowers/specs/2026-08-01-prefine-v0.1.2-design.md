# PreFine v0.1.2 前端定稿与发布设计

状态：已确认视觉设计，待实施计划  
日期：2026-08-01

## 1. 目标与范围

v0.1.2 收录两部分已经确认的前端调整：

- 保留 2026-07-26 定稿并已进入 `main` 的登录页，不改变其比例、文案、蓝色顶层、白色内容层或表单结构。
- 将已确认的金额转换 V4 母版完整落到登录后的正式前端，同时统一侧栏品牌资产。

本版本只调整前端呈现、金额页现有状态的展示方式、版本号和发布说明。金额计算规则、认证流程、税收日历、提醒任务、数据库结构和部署架构保持不变。

## 2. 侧栏品牌

- 侧栏继续显示 Logo 与 `PreFine` 品牌名，二者水平排列并垂直居中。
- Logo 使用透明背景 PNG，不再出现白色方形底板。
- 深色侧栏中的标志保留 Electric Blue 外形，并使用白色内部图形，确保对比度和品牌识别度。
- 桌面侧栏 Logo 的显示尺寸为 `47px × 47px`，品牌名字号为 `21px`，两者间距为 `11px`。
- 登录页仍使用现有定稿尺寸和浅色表面版本；若同一透明资产无法同时保证深浅背景的视觉一致性，则用 CSS 作用域或单独的用途明确资产处理显示，不改变标志造型。
- Logo 仍由仓库品牌目录提供，并由 Vite 作为静态资源发布；不得以内联 SVG 取代正式 PNG，也不得留下过程图或备选 Logo。

## 3. 金额转换页结构

### 3.1 页面标题与方向切换

- 页面标题区域只显示蓝色眉题 `MONEY`、一级标题“金额转换”和方向切换控件。
- 删除“人民币金额的规范表达与日常取用。”以及其他功能解释性副标题。
- 方向切换文案为“数字转大写”和“大写转数字”，两种方向使用同一页面骨架，不因内容不同改变尺寸或排列。

### 3.2 上部双面板

- 桌面端使用两列等宽面板，间距 `14px`；窄屏改为单列堆叠。
- 两个面板的边框、圆角、内边距、最小高度和内部网格完全一致：`1px` 浅灰边框、`12px` 圆角、`20px` 内边距、桌面最小高度 `252px`。
- 左侧标题为“输入金额”，右侧标题为“转换结果”；步骤圆标分别为 `01` 和 `02`。
- 内容区统一为 `92px` 高、`10px` 圆角、浅灰表面；数字输入和大写输入均使用同一高度、字号、行高与内边距。
- 每个面板底部都放置一个全宽复制按钮。两个按钮的高度统一为 `32px`，并与下方三张表示方式卡片的复制按钮使用同一视觉样式。
- 输入区复制当前规范化后的可见输入；结果区复制当前主结果。没有可复制内容时按钮禁用。

### 3.3 “圆”写法归一

- 大写转数字仍允许用户输入常见写法“圆”，后端继续按既有规则规范为“元”。
- 转换成功后，左侧输入面板把主输入更新为规范写法。例如用户输入“肆圆整”，转换后左侧显示“肆元整”。
- 若发生归一，左侧内容区以内敛的次要文字显示“原输入：肆圆整 · 已规范”；不在右侧结果面板显示长段解释，不使用蓝色提示条。
- 右侧只显示正常数字结果，例如 `4.00`。
- 切换转换方向时继续携带规范后的“元”写法。

### 3.4 主转换按钮

- 主转换按钮单独位于双面板下方，不属于任一侧面板。
- 按钮占据工作区完整宽度，与上方双面板组、下方三卡片组的外边缘严格对齐。
- 高度为 `42px`，圆角为 `9px`，深色背景、白色文字，文案为“转换”。
- 请求进行中保持现有禁用与状态反馈，不改变 API 调用或错误处理。

### 3.5 三种其他表示方式

- 主转换按钮下方直接显示“千分位”“快速读数”“英文金额”三张等宽卡片，不显示“便捷写法”等分组主标题。
- 三张卡片在桌面端一行三列，间距 `12px`；窄屏改为单列。
- 卡片使用相同边框、圆角、内边距和内部行结构，最小高度 `126px`。
- 每张卡片底部放置一个 `32px` 高的全宽复制按钮，位置、宽度、圆角与上部面板复制按钮一致。
- 复制成功后，原按钮文案原位变为“已复制”，按钮尺寸不变；新的复制动作会清除上一项状态。
- 不在按钮旁额外增加绿色状态文字；复制失败仍显示现有可访问错误提示。

## 4. 对齐与响应式约束

- 桌面端上部双面板组、主转换按钮、下部三卡片组必须具有相同总宽度。
- 左右面板尺寸相同，两个主内容区尺寸相同，两个置底复制按钮尺寸相同。
- 页面不得因英文金额或大写金额过长发生横向溢出；长文本允许自然换行。
- `820px` 以下侧栏沿用应用现有抽屉行为，金额页双面板和三卡片改为单列。
- `320px` 视口下不得横向溢出，所有输入、结果和按钮仍可操作。

## 5. 组件与状态边界

- `MoneyPage` 继续拥有方向、输入、请求、结果、复制和错误状态，不增加全局状态。
- 抽取或复用一个小型复制按钮组件，使五个复制入口共享同一文案切换、禁用、失败处理和样式契约。
- 金额展示分词只影响视觉着色，复制内容继续使用 API 返回的纯文本。
- 后端响应模型保持不变；前端使用既有 `canonical_uppercase` 与 `normalization_note` 判断是否更新大写输入并显示简短归一状态。
- 输入错误仍在左侧面板内就近显示，并清除陈旧结果；不得用错误状态改变左右面板的基本结构。

## 6. 可访问性

- 页面保留一个可见的一级标题“金额转换”。
- 两个输入方向都使用可见标签和正确关联的表单控件。
- 复制按钮通过可访问名称区分目标，视觉文案仍统一为“复制”或“已复制”。
- 键盘用户可以依次访问方向切换、输入、两个主复制按钮、转换按钮和三种表示方式的复制按钮。
- 焦点继续使用现有 Electric Blue 可见轮廓；颜色不是复制成功、归一或错误状态的唯一信息载体。

## 7. 测试与验收

### 7.1 Vitest / React Testing Library

- 两种转换方向均呈现“输入金额”和“转换结果”的对称结构。
- 页面不再出现被删除的副标题或“便捷写法”标题。
- 主结果和三种表示方式都能复制；点击后同一按钮原位显示“已复制”，其他按钮恢复“复制”。
- 输入“肆圆整”成功后，左侧更新为“肆元整”并显示简短原输入状态，右侧显示 `4.00`。
- 切换方向继续使用规范后的输入。
- 复制失败和 API 错误仍有可访问提示。

### 7.2 AppShell 与品牌资产

- 侧栏使用正式透明 PNG，尺寸类与可访问文本保持正确。
- 品牌身份测试更新为新透明资产的准确 SHA-256，并证明品牌目录仍只有批准的正式 Logo 资产。
- 构建产物包含最终 Logo，登录页和侧栏引用均可正常加载。

### 7.3 Playwright 与视觉验收

- 登录页与 2026-07-26 定稿保持一致。
- 桌面金额页中，上部双面板组、转换按钮和下部三卡片组总宽度一致。
- 左右面板、内容区和置底复制按钮分别同尺寸。
- 桌面端三卡并排，窄屏单列；`320px` 无横向溢出。
- 对数字转大写、大写转数字、“圆”归一和复制状态执行完整用户流。

## 8. v0.1.2 发布

- 将后端包、前端包、健康检查和系统页面显示版本统一升级到 `0.1.2`。
- 根目录 `RELEASE_NOTES.md` 只描述 v0.1.2：包含已经定稿的登录页、透明侧栏品牌和金额转换工作区调整。
- 正式代码和文档验证通过后直接提交并推送 `main`；本地不构建 Docker 镜像。
- 等待 `main` 工作流成功并确认 `latest` 镜像来自目标提交。
- 创建并推送带注释标签 `v0.1.2`，由 GitHub Actions 构建 `linux/amd64` 与 `linux/arm64` 镜像并创建 GitHub Release。
- 最终核对本地 `HEAD`、远端 `main`、`v0.1.2` 标签、GitHub Release 目标和镜像 OCI revision 指向同一提交；`latest` 与 `0.1.2` 均可匿名拉取且包含两个架构。

## 9. 非目标

- 不修改登录认证逻辑、管理员凭据、会话、Cookie 或安全策略。
- 不改动人民币金额算法、金额上限、精度规则或 API 字段。
- 不修改税收日历、税务档案、提醒调度、SMTP 或数据库。
- 不在本地打包 Docker，不新增运行时依赖、字体、图标库或第三方 UI 框架。
- 不创建功能分支或 Pull Request；本轮按用户确认直接发布 `main`。
