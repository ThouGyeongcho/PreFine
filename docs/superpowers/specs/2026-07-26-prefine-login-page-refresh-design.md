# PreFine 登录页视觉刷新设计

状态：已确认设计，待实施计划
日期：2026-07-26

## 1. 目标与范围

本次刷新只调整登录页的视觉层级、表单文案、响应式布局和交互状态，不改变认证接口、会话机制、登录成功后的跳转或后端行为。

目标是让登录页更精致、紧凑，并强化 PreFine 自有品牌识别。页面继续遵守原始产品约束：只提供单一管理员登录表单，不增加注册、找回密码、记住登录、首次启动向导、版本页脚或宣传内容。

本规范覆盖并细化原始 PreFine v1 设计中的登录页视觉规则；发生冲突时，仅登录页以本规范为准，其他页面继续遵守原始规范。

实施文件为：

- `frontend/src/pages/LoginPage.tsx`
- `frontend/src/pages/LoginPage.test.tsx`
- `frontend/src/styles.css`
- `frontend/e2e/critical-flows.spec.ts`

不新增图片资产，继续使用 `/prefine-logo-512.png`。

## 2. 已确认的视觉结构

### 2.1 页面与登录框

- 页面背景为纯白色，不使用渐变、几何图形、水印或阴影。
- 登录组件在视口中水平、垂直居中。
- 桌面端登录框总宽度为 `360px`。
- 登录框由蓝色顶层和白色内容层组成：
  - 蓝色顶层使用主题色 `#3E6AE1`，总高度 `20px`，实际在白色内容层上方露出 `10px`。
  - 蓝色顶层顶部圆角为 `14px`。
  - 白色内容层顶部为平直边，不使用圆角，不在蓝白接触处形成弧形缺口。
  - 白色内容层只保留底部 `12px` 圆角。
  - 白色内容层左右和底部使用 `1px solid #EEEEEE`，顶部无边框。
- 白色内容层桌面端内边距为：顶部 `36px`、左右 `27px`、底部 `39px`。加上两侧各 `1px` 边框后，外框边缘到表单边缘的视觉距离各为 `28px`。
- 不使用投影；层次只由蓝色顶层、白色表面和细边界表达。

### 2.2 品牌与标题比例

品牌区全部居中，顺序固定为：

1. PreFine 标志
2. `PreFine` 品牌名
3. `登录` 页面标题

桌面端尺寸为：

- 标志：`74px × 74px`
- 标志与品牌名间距：`13px`
- 品牌名：`42px`、字重 `500`、字距 `0.11em`
- 品牌名与“登录”的视觉间距：`23px`
- “登录”：`15px`、字重 `400`、颜色 `#5C5E62`、字距 `0.24em`
- “登录”与表单间距：`31px`

品牌名仍然写作连续文本 `PreFine`。横向拉伸使用 CSS `letter-spacing`，不在 DOM 文本中插入半角空格，避免影响复制、搜索和读屏。

页面标题只显示“登录”，不显示“管理员登录”，避免与字段标签“管理员账号”重复。

### 2.3 表单

- 桌面端表单内容宽度为 `304px`，在登录框内居中。
- 字段顺序为“管理员账号”“密码”。
- 标签位于输入框上方，字号 `12px`，颜色 `#393C41`。
- 标签与输入框间距为 `7px`。
- 输入框高度为 `43px`，圆角为 `10px`，背景为白色，边框为 `1px solid #EEEEEE`。
- 两个字段组之间保持 `16px` 间距。
- 主按钮与最后一个字段组之间保持 `22px` 间距。
- 主按钮高度为 `43px`，圆角为 `10px`，背景为 `#171A20`，文字为白色，按钮文案为“登录”。
- 页面不显示“使用部署时配置的管理员账号继续”等辅助说明。

## 3. 响应式行为

- `360px` 是登录框的最大宽度，不是固定最小宽度。
- 页面左右至少保留 `16px` 安全间距。
- 当视口不足以容纳 `360px` 登录框时，登录框宽度收缩为可用宽度。
- 内容层左右内边距可在窄屏收至 `20px`，表单宽度使用 `min(304px, 100%)`。
- 品牌、标题、字段和按钮保持相同的相对顺序，不切换为横排。
- 已确认的品牌字级比例不因断点单独改变；只允许整个可用内容宽度收缩。
- 页面必须在 `320px` 宽视口下无横向溢出、裁切或核心操作阻断。

## 4. 交互与状态

### 4.1 基础行为

- 认证请求继续使用 `POST /api/auth/login`，请求体字段仍为 `username` 和 `password`。
- 用户名输入继续使用 `autocomplete="username"`。
- 密码输入继续使用 `type="password"` 和 `autocomplete="current-password"`。
- 表单继续支持 Enter 提交。
- 登录成功后继续刷新 `current-user` 查询并跳转到工作台。

### 4.2 焦点、提交中与错误

- 所有输入框和按钮使用可见的主题蓝键盘焦点，不移除全局 `:focus-visible`。
- 提交中按钮禁用，文案显示“正在登录…”，避免重复请求。
- 服务端返回的中文认证错误继续原样显示；未知错误显示“登录失败，请稍后重试”。
- 错误提示放在密码字段与按钮之间，限制在 `304px` 表单宽度内。
- 错误提示使用现有危险色体系和 `role="alert"`，不得清空用户已输入的密码。
- 错误出现可以向下扩展登录框，但不得覆盖按钮、输入框或造成横向溢出。

## 5. 组件与样式边界

`LoginPage` 继续拥有登录请求、字段状态、错误映射和跳转逻辑。视觉结构不拆分新的 React 组件，避免为单页静态布局增加不必要抽象。

登录页样式使用明确的 `login-*` 类名作用域。共享颜色变量、全局焦点规则和基础字体继续复用现有设计系统；新的蓝色顶层、紧凑登录框和表单尺寸只影响登录页，不修改工作台、金额工具或税收日历的卡片与按钮。

## 6. 可访问性

- 页面保留单一 `h1`，可见文本为“登录”。
- 登录区域通过 `aria-labelledby` 关联该标题。
- PreFine 标志旁已有可见品牌名，因此图片作为装饰图像使用空 `alt`，避免读屏重复播报品牌。
- 每个输入框继续由可见 `label` 关联，不以 placeholder 代替标签。
- 错误使用 `role="alert"`。
- 颜色不作为错误、焦点或提交状态的唯一信息来源。
- 键盘用户能够依次访问管理员账号、密码和登录按钮。

## 7. 测试与验收

### 7.1 Vitest / React Testing Library

- 显示确认后的 PreFine 标志和品牌名。
- 页面只存在一个名为“登录”的一级标题。
- 字段标签为“管理员账号”和“密码”。
- 正确账号密码仍能提交并跳转到工作台。
- 提交中按钮显示“正在登录…”并禁用。
- 服务端错误继续显示且密码不被清空。

### 7.2 Playwright

- 桌面端登录框居中，蓝色顶层和白色内容层均可见。
- `320px` 窄屏无横向溢出，账号、密码和登录按钮均可操作。
- 键盘 Tab 顺序和焦点可见性正确。
- 登录成功后进入工作台。

### 7.3 视觉验收

- 蓝色是白色登录框背后的独立顶层，不表现为细边框。
- 蓝色顶层顶部有圆角，蓝白交界是平直水平线。
- 外框宽度为 `360px`，表单宽度为 `304px`，单侧视觉留白约 `28px`。
- 标志、品牌名和“登录”均居中，比例为 `74px / 42px / 15px`。
- 页面无背景装饰、投影、注册入口、找回密码入口或额外说明。

## 8. 非目标

本次不修改后端认证、登录限速、Cookie、安全策略、会话时长、管理员凭据来源或 API 错误格式；不刷新应用内其他页面；不推送远程仓库，也不构建或发布 Docker 镜像。推送和 Docker 打包在前端整体定稿后单独执行。
