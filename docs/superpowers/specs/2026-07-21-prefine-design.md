# PreFine v1 设计规格

状态：已确认设计，待实施计划
日期：2026-07-21

## 1. 产品目标

构建一个面向中国大陆财务人员的私有化 Web 工具包。首版提供人民币金额大小写双向转换、按地区展示的税收日历，以及税期截止邮件提醒。产品必须能通过单个 Docker 容器部署、使用单一管理员账号登录，并为后续增加更多财务工具保留清晰的模块边界。

首版成功标准：

- 使用一个镜像和一个持久化数据卷即可启动，不依赖外部数据库。
- 管理员凭 Docker 环境变量中的账号密码登录，未登录不能访问业务页面或业务 API。
- 金额转换使用十进制定点计算，支持负数，超过两位小数直接报错，反向解析只接受系统自身生成的规范大写格式。
- 税收日历可切换国家税务总局 12366 当前公开的 36 个地区，并按月份查看税种及起止日期。
- 税历按需拉取并持久化缓存；官网不可用时继续展示最后一次成功数据，并明确标识同步状态。
- 税历右侧默认逐项展示 12366 原始文字、顺序和日期；用户可切换到按纳税人身份及核定／关注事项筛选的“我的税务清单”。
- 固定邮箱可按税务工具内设置的地区、纳税身份、核定／关注事项和提前天数接收截止提醒，重复任务不会重复发信。

首版不包含多用户、角色权限、访客订阅、多币种、英文金额、自定义税历、税历本地编辑、iCal 导出和多实例横向扩容。

## 2. 用户体验与视觉设计

### 2.1 信息架构

采用已确认的 B 方案：深色固定侧边导航加专业工作区。

- 登录后默认进入“工作台”，显示两个工具入口；税务档案配置完整后显示个性化近期税期摘要，否则显示完成税务设置的提示，不用未筛选的官方事项冒充企业清单。
- 一级导航为“工作台”“金额大小写转换”“税收日历”“系统设置”。
- 金额页采用左右双面板：数字金额、方向切换、中文大写；结果可一键复制，错误在输入面板内联显示。
- 税历页采用月历加右侧详情：顶部切换月份和地区；右侧在“官方原文”和“我的税务清单”间即时切换。官方模式完整保留 12366 原文和日期，个性化模式按企业税务档案筛选。
- 每个工具的业务设置放在该工具主内容下方。税务工具下方常驻显示默认模式、纳税人身份、核定／关注事项、默认地区、提醒提前天数、手动同步和测试邮件；金额工具下方显示当前不可变的转换规则，未来新增的金额偏好也只放在金额工具内。
- “系统设置”只展示部署级状态和配置是否完整，例如 SMTP 连接状态、数据库、调度器和版本。管理员账号、密码、会话密钥及 SMTP 密钥只来自环境变量，不在页面中显示或修改。
- 登录页为单一居中表单，不提供注册、找回密码或首次启动向导。

### 2.2 视觉规范

视觉语言参考 [Tesla Design MD](https://getdesign.md/tesla/design-md)，只借鉴可观察的设计模式，不使用 Tesla 商标或品牌素材。

- 主色 `#3E6AE1`，主文字 `#171A20`，正文 `#393C41`，次要文字 `#5C5E62`。
- 页面底色 `#FFFFFF`，次级表面 `#F4F4F4`，分隔线 `#EEEEEE` / `#D0D1D2`。
- 字体优先 Inter、苹方、微软雅黑和系统无衬线字体；仅使用 400 与 500 字重。
- 基础间距为 8px；按钮与输入框圆角 4px，内容卡片圆角 12px。
- 默认不使用投影；层级依靠留白、色块、透明度和细分隔线表达。
- 主按钮高 40px；焦点态使用 Electric Blue 边框，所有交互必须支持键盘操作和可见焦点。
- 桌面端侧栏宽约 190px。窄屏下侧栏改为抽屉，金额面板纵向堆叠，税历详情移至月历下方；月历本体保留七列并允许最小宽度滚动。

## 3. 技术架构

### 3.1 运行形态

- 后端：Python 3.12、FastAPI、Pydantic v2、SQLAlchemy 2、Alembic、HTTPX、APScheduler、aiosmtplib。
- 前端：React、TypeScript、Vite、React Router、TanStack Query。
- 存储：SQLite，数据库文件位于 `/data/prefine.db`。
- 部署：前端构建产物由 FastAPI 同源托管；最终产出一个多阶段构建的 Docker 镜像和一个 `docker-compose.yml` 示例。
- 进程：容器只运行一个 Uvicorn worker。Web 请求、定时同步和邮件调度处于同一进程，避免多实例重复任务。
- 健康检查：`GET /api/health` 不需要登录，只返回进程状态、数据库可用性和版本，不泄露配置值。

容器以非 root 用户运行，`/data` 必须挂载持久化卷。启动时执行受版本控制的 Alembic 迁移；迁移失败则容器启动失败，不带病运行。

### 3.2 模块边界

- `money`：纯业务模块，负责数字校验、十进制规范化、人民币大写编码和严格反向解析，不依赖数据库或 Web 框架。
- `tax_source`：隔离 12366 的地区列表和月度税历接口、字段映射、超时、校验及错误分类。上游格式变化只影响该适配器。
- `calendar`：负责缓存策略、事务替换、月份查询、同步状态和并发去重。
- `tax_profile`：维护规范事项目录、纳税人身份标签、上游文字映射、个性化筛选和“其他待确认”结果，不修改或覆盖官方原文。
- `auth`：负责环境变量凭据、登录限速、签名会话和请求来源校验。
- `reminders`：负责到期计算、邮件组装、发送去重、失败重试和测试邮件。
- `web`：FastAPI 路由、统一错误响应、静态前端托管。

## 4. 核心行为

### 4.1 人民币金额转换

数字输入规则：

- 接受可选前导负号、纯数字或正确三位分组的千分位、小数点和最多两位小数。
- 不接受科学计数法、货币符号、空白夹杂、错误千分位或超过两位小数。
- 绝对值上限为 `999,999,999,999,999.99`；使用 `Decimal`，禁止二进制浮点参与金额计算。
- `-0`、`-0.00` 规范化为 `0.00`；零输出为“零元整”。
- 大写输出只使用“负、零壹贰叁肆伍陆柒捌玖、拾佰仟、万亿、元角分、整”。

反向解析规则：

- 只接受系统编码器能够生成的完整字符串，不接受“人民币”前缀、“圆”“正”、小写中文数字或猜测性纠错。
- 解析后必须重新编码并与原始输入完全一致，否则返回格式错误；这保证反向结果不存在多义性。
- 页面方向切换时保留已验证的当前值；无效输入不自动转换、不静默舍入。

### 4.2 税收日历同步

数据源为国家税务总局 12366 办税日历页面当前使用的服务端接口：

- 地区列表：`/core-plugins/12366/js/provinces.json`。
- 月数据：`POST /bsfw/calendar/getCalendarListForMonth`，表单字段为地区机构编码 `ssjg` 和月份 `bssj=YYYY-MM`。
- 首版内置当前 36 个地区的名称和机构编码作为离线种子，并可在同步成功后刷新地区元数据。

这些接口没有正式开放文档，因此实现必须把它们视为易变上游：

- 每次响应先验证 HTTP 状态、业务 `statusCode`、列表类型和必要日期字段，再进入数据库事务。
- 单次请求超时 10 秒，只允许一次短退避重试；同一地区月份同时只允许一个同步任务。
- 不进行全地区全年爬取。用户首次访问某地区月份且无缓存时同步等待；若失败，返回可重试错误。
- 缓存未超过 24 小时时直接返回。缓存过期时先返回旧数据并标记 `stale=true`，再触发后台刷新。
- 每天北京时间 08:00 刷新默认提醒地区的当前月和下月，以及过去 30 天内访问过的月份缓存。
- 手动“立即同步”只同步当前所选地区月份，等待完成后明确显示成功或失败。
- 只有完整校验成功的响应才事务性替换该地区月份的缓存。失败或响应畸形时保留旧数据。

每个缓存行保留来源事件 ID、地区、缓存月份、起止日期、原始税种文本、拆分后的税种数组、来源机构、来源创建时间和抓取时间。若上游缺少事件 ID，使用地区、日期范围和原始税种文本生成稳定哈希。

页面应在所有税历视图显示来源链接和最后成功同步时间，并声明数据仅供办税安排参考，最终以主管税务机关最新通知为准。

### 4.3 官方原文与企业税务档案

税历右侧提供两种即时切换的视图，默认视图为“官方原文”：

- 官方模式按上游事件逐项显示起止日期和原始 `bssz` 文本，不删减、不重排、不替换名称。系统可在后台拆分文本用于筛选，但不能用拆分结果重建官方视图。
- “我的税务清单”使用同一批官方事件，只隐藏明确判定与当前企业无关的事项，不生成上游不存在的截止日期或税种说明。
- 企业税务档案包含纳税人身份 `general_taxpayer` / `small_scale_taxpayer`、核定／关注事项代码数组、默认地区、默认显示模式和提醒提前天数。身份与事项没有配置完整时，个性化视图显示配置引导，不猜测企业属性。
- 一般纳税人和小规模纳税人的专属条目通过显式身份标签筛选；没有身份前缀的共同事项再依据用户勾选的事项代码筛选。
- 初始规范目录覆盖上游当前出现的增值税、消费税、城市维护建设税、教育费附加、地方教育附加、文化事业建设费、企业所得税、个人所得税、土地增值税、资源税、环境保护税、车船税、政府性基金及财务会计报告等事项。目录区分税、费／基金和报表，但统一允许用户关注。
- 每个目录项维护稳定代码、展示名称、常见上游别名、身份适用范围和事项类别。映射使用经过测试的精确别名及受限规则，不用模糊相似度猜测。
- 上游出现无法映射的新文字时，个性化视图必须显示“其他待确认”，附带原文、日期和查看官方模式入口；未知事项不得静默隐藏。
- “核定／关注事项”由用户自行配置，不表示系统已连接电子税务局或读取企业真实核定信息。页面和邮件持续显示该说明。

所有税务业务设置放在税历主内容下方的“税务工具设置”面板。修改保存后，右侧个性化视图、工作台摘要和后续提醒使用同一份设置；官方原文始终可查看。设置保存失败时保留原值并在面板内提示，不让页面显示尚未持久化的配置。

### 4.4 邮件提醒

- 在税务工具设置中选择提醒地区、纳税人身份和核定／关注事项；默认提前天数为 7、3、1 天，可添加或移除 0–30 范围内的整数。
- 固定收件邮箱和 SMTP 参数来自环境变量。缺少必要参数时核心工具仍可使用，但提醒状态显示“未配置”，测试邮件不可发送。
- 调度器每天 09:00–18:00 每小时检查一次。每次先确保提醒地区当前月和下月缓存可用，再查找 `截止日 - 当天` 命中任一提前天数的事件。
- 提醒使用与“我的税务清单”完全相同的筛选器。税务档案未配置完整时不发送正式提醒，并在工作台提示完成配置。
- 相同地区、截止日和提前天数的相关事项合并成一封邮件，正文列出筛选后的事项、税期范围、数据更新时间和 12366 来源链接。无法映射的新事项作为“其他待确认”一并列出，防止漏报风险。
- 主题格式为 `[财务工具包] {地区}：{N}天后有税务事项截止`；截止当天使用“今天截止”。
- 发送成功后写入唯一去重记录：地区、截止日、提前天数、收件邮箱指纹。SMTP 失败不记为成功，后续小时任务继续重试，成功后不再重复发送。
- 容器在 09:00–18:00 之间重启时立即执行一次补偿检查；在窗口外启动则等待下一次计划任务。
- “发送测试邮件”使用独立主题，不写业务提醒去重记录。

## 5. 接口与数据

除健康检查和登录接口外，所有 `/api` 路由都要求有效管理员会话。

主要接口：

- `POST /api/auth/login`：接收用户名和密码，成功后设置 HttpOnly 会话 Cookie。
- `POST /api/auth/logout`、`GET /api/auth/me`：退出和获取当前会话状态。
- `POST /api/money/to-uppercase`：输入字符串金额，返回规范数字字符串和人民币大写。
- `POST /api/money/to-number`：输入严格大写字符串，返回规范数字字符串。
- `GET /api/regions`：返回可选地区。
- `GET /api/calendar?region_code=...&month=YYYY-MM`：返回月事件、未修改的官方原文、按当前税务档案生成的个性化结果、未映射事项、缓存新鲜度和同步状态。
- `POST /api/tools/tax/sync`：从税务工具内手动同步指定地区月份。
- `GET /api/tools/tax/settings`、`PUT /api/tools/tax/settings`：读取和更新默认模式、纳税人身份、核定／关注事项、提醒地区和提前天数。
- `POST /api/tools/tax/test-email`：使用当前税务工具设置向固定收件地址发送测试邮件。

统一错误格式为 `{ "code": "stable_code", "message": "面向用户的中文说明", "details": {} }`。输入错误使用 422，未认证使用 401，上游无缓存且同步失败使用 503；上游失败的内部响应正文不得透传给前端。

SQLite 表：

- `calendar_events`：以 `region_code + cache_month + source_event_id` 唯一，保存月缓存事件。
- `calendar_sync_state`：每个地区月份的最后访问、最后尝试、最后成功、状态和截断后的错误摘要。
- `tax_catalog_items`：保存随版本提供的稳定事项代码、类别、展示名称、身份适用范围和启用状态。
- `tax_catalog_aliases`：保存经过测试的上游精确别名及映射规则版本，便于上游文字变化时独立升级。
- `tool_settings`：以 `tool_key` 唯一保存各工具经 Pydantic 校验的设置 JSON；首版使用 `tax_calendar`，包含默认模式、身份、事项代码、默认地区和提前天数。
- `email_dispatches`：提醒去重键、状态、尝试次数、最后错误、发送时间。
- `schema_version` 由 Alembic 管理；不建立用户表或明文凭据表。

## 6. 安全与配置

必需环境变量：

- `ADMIN_USERNAME`
- `ADMIN_PASSWORD`
- `SESSION_SECRET`，至少 32 个随机字符

邮件功能环境变量：

- `SMTP_HOST`、`SMTP_PORT`、`SMTP_USERNAME`、`SMTP_PASSWORD`
- `SMTP_FROM`、`REMINDER_TO_EMAIL`
- `SMTP_USE_TLS` 或 `SMTP_STARTTLS`，两者不能同时启用

其他配置：

- `TZ=Asia/Shanghai`
- `DATA_DIR=/data`
- `COOKIE_SECURE=false`，通过 HTTPS 反向代理部署时设为 `true`

安全要求：

- 密码和 SMTP 密钥不得写入数据库、前端包、日志、健康检查或错误响应。
- 登录按来源 IP 限制为 15 分钟内最多 5 次失败尝试；成功登录清除该 IP 计数。
- 会话有效期 12 小时，Cookie 设置 HttpOnly、SameSite=Lax，并依据 `COOKIE_SECURE` 设置 Secure。
- 所有改变状态的 Cookie 认证请求校验 Origin/Host；JSON API 不接受跨域凭据。
- Docker 文档明确建议生产环境置于 HTTPS 反向代理后，并限制容器和 SQLite 卷的访问权限。

## 7. 失败处理与可观测性

- 首页和税历页区分“最新”“过期缓存”“同步失败且使用旧数据”“无数据”四种状态。
- 上游错误记录结构化日志：地区、月份、阶段、错误类别和耗时；不记录 Cookie、密码、SMTP 凭据或完整上游异常正文。
- 邮件日志记录提醒键、尝试次数和 SMTP 错误类别；收件地址只记录不可逆指纹。
- `/api/health` 检查数据库读写连接和调度器状态；上游 12366 不作为容器健康条件，避免官网故障触发容器重启循环。
- 数据库写入、同步替换和设置更新必须使用事务。SQLite 启用 WAL、外键和合理的 busy timeout。

## 8. 测试与验收

### 8.1 自动化测试

- 金额单元测试覆盖零、负数、整数、角分、内部零、万亿边界、最大值、错误千分位、科学计数法、三位小数和严格反向回环。
- 税源适配器使用固定响应夹具覆盖正常、空列表、缺字段、非法日期、业务失败、HTTP 超时和上游字段变化。
- 缓存测试覆盖首次同步、24 小时新鲜度、过期先返回、失败保留旧数据、成功事务替换和并发去重。
- 税务档案测试覆盖一般纳税人、小规模纳税人、共同事项、多选事项、空档案、精确别名、未知事项和“官方原文不被筛选器改写”的不变量。
- 提醒测试固定北京时间，覆盖档案筛选、未知事项提示、7/3/1/0 天、跨月、同日合并、成功去重、失败重试、重启补偿和收件地址指纹。
- 认证测试覆盖正确/错误密码、限速、过期会话、Cookie 属性、Origin 拒绝和未登录 API。
- 前端组件与端到端测试覆盖登录、双向转换、复制、地区/月切换、官方／个性化视图切换、税务工具内设置、未知事项、缓存告警、测试邮件和移动布局。
- Docker 冒烟测试覆盖全新卷启动、健康检查、登录、数据库持久化和容器重启后缓存保留。

真实 12366 接口只提供一个手动契约检查，不加入每次 CI，以免外部网络或上游波动造成不稳定构建。

### 8.2 验收场景

1. 使用示例环境变量和命名卷启动容器，健康检查通过，管理员可以登录。
2. 输入 `-128650.32` 得到“负壹拾贰万捌仟陆佰伍拾元叁角贰分”，反向转换恢复规范数字；输入三位小数被拒绝且不改变数值。
3. 切换任一支持地区和月份后得到税历；右侧默认原样展示官方文字和日期。配置一般纳税人或小规模纳税人及关注事项后，个性化视图只显示匹配内容，未知事项进入“其他待确认”。
4. 断开外网或模拟 12366 失败后，已缓存月份仍可查看并显示过期/失败提示；官方原文不因筛选规则或同步失败被改写。
5. 部署 SMTP 环境变量，并在税务模块下方配置身份、事项、默认地区和 7/3/1 天后，测试邮件成功；正式提醒只包含相关事项和待确认事项，同一截止日只发送一次，SMTP 短时失败后能够重试。
6. 重启容器后工具设置、税历缓存、同步状态和发送去重记录均保留。
7. 桌面端符合确认的 B 方案；手机端可完成登录、金额转换、日历双模式查看和工具内设置操作，无横向溢出阻断核心操作。

## 9. 明确假设

- 首版只面向中国大陆税历和人民币，不对税务数据作法律保证。
- 12366 页面接口属于未文档化上游，适配器、持久化缓存和来源状态提示是必需设计，不将其当作稳定公共 API。
- 部署者负责提供可访问 12366 和 SMTP 服务器的网络环境。
- 系统只支持单容器单 worker；如果未来需要多副本，必须先将调度和发送去重迁移到共享数据库/任务队列。
- 默认提醒地区为空；税历首次打开时优先使用浏览器上次选择，其次使用税务工具保存的默认地区，仍为空时展示北京但不启用邮件提醒。
- 税历默认显示“官方原文”；企业税务档案初始为空，用户主动配置身份和核定／关注事项后才启用个性化清单和正式提醒。
- 个性化清单是对 12366 原文的本地辅助筛选，不等同于企业在电子税务局中的真实税种核定结果。
- 视觉规范使用 Tesla 风格分析作为灵感，产品名称、图标和素材保持自有，不暗示任何品牌关联。
