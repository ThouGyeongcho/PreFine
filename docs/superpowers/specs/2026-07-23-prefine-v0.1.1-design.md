# PreFine v0.1.1 设计规格

状态：已确认设计，待实施计划
日期：2026-07-23

## 1. 目标与范围

v0.1.1 聚焦已上线版本的登录品牌呈现和金额工具体验，不改变认证、税务日历、提醒或部署架构。

本版本必须完成：

- 使用仓库中已确认的 PreFine Logo，重新设计登录页品牌区并消除重复命名。
- 将工具及页面主标题统一为“金额转换”。
- 统一金额转换两种方向的输入区、结果区、字号、间距和按钮尺寸。
- 修复结果复制在 Clipboard API 不可用或受限时无反应的问题。
- 允许人民币大写中的“圆”作为“元”的常见写法，并提示规范写法。
- 删除常驻的“当前转换规则”面板，把相关限制放进具体错误提示。
- 为两个转换方向都提供千分位、中文快速读数和完整英文金额。
- 将应用版本升级至 `0.1.1`，并发布只描述本版本变化的简明 Release Note。

## 2. 登录页与品牌

登录页沿用既定的白色表面、细边框、无阴影、Electric Blue 和 8px 间距体系。

- 用 `assets/branding/prefine-logo-512.png` 替换临时的“财”字图标。前端构建必须直接使用这一已确认资产，不生成第二套 Logo。
- Logo 在登录卡片内按 64px 正方形显示，保持原始比例，不增加底色或圆角容器。
- 品牌名 `PreFine` 使用约 30–32px、500 字重，作为 Logo 下方的主要品牌标题。
- 原“登录 PreFine”改为“管理员登录”，避免与品牌名重复；辅助文案保持“使用部署时配置的管理员账号继续。”
- 登录表单宽度、4px 控件圆角、40px 按钮高度和可见焦点继续遵循原设计规范。
- 登录页和应用侧栏引用同一 Logo 资产，避免登录前后品牌不一致；侧栏 Logo 保持紧凑尺寸。

## 3. 金额转换工作区

### 3.1 名称和布局

- 导航、工作台入口和页面主标题中的“金额大小写转换”统一改为“金额转换”。方向切换按钮仍明确写“切换为大写转数字”或“切换为数字转大写”。
- 桌面端保持左右双面板，小屏保持纵向堆叠。
- 两种方向均使用同一个固定高度的多行输入控件，默认高度 128px；输入字号、行高、内边距完全一致。
- 左右面板使用相同的最小高度和内部节奏。主转换按钮与复制按钮均为 40px 高、相同字号和相同横向宽度。
- 主结果区使用统一的 22px 响应式上限，不因方向切换出现明显字号跳变。
- 删除页面底部“当前转换规则”及三列规则卡片。

### 3.2 转换结果与便捷写法

转换成功后，右侧结果面板先显示当前方向的主结果，再显示“便捷写法”。两个方向返回相同的完整结果模型，因此从数字转大写或从大写转数字都会显示以下三项：

1. **千分位**：每三位分组；整数不附加 `.00`，非零角分保留两位，例如 `1000000.00 → 1,000,000`、`1234.50 → 1,234.50`。
2. **快速读数**：按中文计数习惯从右向左每四位断组，依次插入“万”“亿”，完整保留原金额的每一位数字，不缩放、不舍入。例如 `785934 → 78万5934`、`785934455.00 → 7亿8593万4455`、`1000000 → 100万`。不足一万直接显示原数字；非零角分保留在末组，负号保持不变。
3. **英文金额**：使用完整英文单词、句首大写，不使用全大写。例如 `1000000 → One million yuan only`。非零小数用 fen 表达，例如 `1000000.32 → One million yuan and thirty-two fen only`；负数以 `Negative` 开头。整数部分使用短级差命名 `thousand`、`million`、`billion`、`trillion`，覆盖现有金额上限。

主结果和三项便捷写法均提供独立复制按钮。复制成功时在对应项目内显示“已复制”；新的复制动作会清除上一次状态。

### 3.3 数位对照着色

着色仅用于视觉辅助，不改变复制内容、API 文本或屏幕阅读器读到的完整顺序：

- 快速读数中的分组单位“万”“亿”使用既定主色 `#3E6AE1`，阿拉伯数字、负号和小数部分保持主文字色。
- 人民币大写结果中的数值汉字“零壹贰叁肆伍陆柒捌玖”保持主文字色；单位及格式汉字“拾佰仟万亿元角分整”和负号“负”使用 `#3E6AE1`。
- 分词由前端按固定字符集合完成，只生成展示用文本片段；复制按钮复制未插入标记的原始完整字符串。
- 色彩不能成为唯一信息载体，字符本身和原有顺序仍足以表达金额；蓝色与白色、浅灰表面必须保持可读对比度。

## 4. 大写兼容与错误处理

### 4.1 “圆”兼容

- 反向解析在严格校验前只做一项兼容归一化：把单个人民币单位“圆”替换成“元”。
- 归一化后仍必须通过现有的无歧义解析、金额范围校验和规范回编码校验。小写中文数字、人民币前缀、“正”替代“整”、缺失单位、相邻数字或非法单位顺序仍然拒绝。
- 转换成功后 API 返回规范人民币大写。输入中使用过“圆”时，结果区显示非错误提示：`已按标准写法转换：“圆”应写作“元”。`
- 方向切换时使用规范化后的“元”写法，不把“圆”继续带入下一次输入。

### 4.2 错误信息

移除“仅接受本系统生成的规范大写格式”文案。错误必须说明当前输入哪里不符合要求：

- 数字精度错误：`金额最多保留两位小数。`
- 数字格式错误：`请输入数字金额，可使用规范千分位，最多保留两位小数。`
- 超出范围：保留明确的金额范围上限。
- 大写格式错误：`请输入完整的人民币大写金额，例如“壹佰元整”。可使用“圆”，系统会转换为标准写法“元”。`

输入错误继续在左侧输入控件附近显示，不清空用户输入，也不展示旧结果。

### 4.3 复制失败

- 首选异步 Clipboard API。
- 当 Clipboard API 缺失、拒绝或抛错时，使用临时只读文本控件和浏览器复制命令作为兼容回退。
- 两种方式均失败时显示 `复制失败，请手动选择文本复制。`，不得静默无反应。
- 复制按钮必须支持键盘操作，并保留可见焦点。

## 5. 架构与数据流

金额计算继续集中在 `backend/app/money.py`，并且所有金额计算只使用 `Decimal`：

- 数字解析和人民币大写编码维持现有职责。
- 大写解析增加“圆”到“元”的有限归一化，并返回规范大写。
- 新增纯函数生成千分位、按四位完整断组的快速读数和英文金额。
- 两个金额 API 使用一致的响应模型，返回规范数字、规范人民币大写、千分位、快速读数和英文金额。新增字段为向后兼容扩展。

前端 `MoneyPage` 只负责方向状态、调用 API、展示统一结果模型、复制状态和可访问提示，不在 JavaScript 中重新计算金额，避免二进制浮点参与。

## 6. 测试与验收

后端测试必须覆盖：

- `圆` 可转换并返回含“元”的规范大写；原有非法大写仍被拒绝。
- 千分位对整数、角分、负数、零和上限输出正确。
- 快速读数的不足一万、万、亿、多级组合、小数和负数，且每种情况都完整保留原数字、绝不舍入。
- 英文金额的零、整数、角分、负数和跨 thousand/million/billion/trillion 边界。
- 两个 API 返回一致的扩展结果模型及稳定错误结构。

前端测试必须覆盖：

- 登录页加载已确认 Logo，仅显示一次 `PreFine`，标题为“管理员登录”。
- 页面和导航显示“金额转换”。
- 两种方向使用同一输入结构并展示三种便捷写法。
- 快速读数中的“万/亿”和人民币大写结果中的单位汉字使用主色，数字字符保持主文字色；复制值不含展示标记。
- 使用“圆”成功后显示标准写法提示。
- Clipboard API 成功、回退成功和完全失败三条路径。
- 每一项复制状态相互独立且可重置。
- 原有输入保留、方向切换和错误联显行为不回归。

发布前运行后端 pytest、Ruff、前端 lint/Prettier、Vitest、生产构建和 Playwright 关键流程。视觉验收同时检查桌面双栏和窄屏堆叠，确保输入框、结果区和按钮对齐。

## 7. 版本与发布

- 后端包版本、前端包版本和版本相关测试升级为 `0.1.1`。
- 仓库根目录维护一份只包含 v0.1.1 变化的 Release Note；GitHub Release 使用该文件，不自动混入完整提交历史。
- 所有本地验证通过后提交并推送 `main`，等待 `latest` 镜像工作流成功。
- 随后创建并推送带注释标签 `v0.1.1`，等待双架构 `0.1.1` 镜像和对应 GitHub Release 成功，再核对标签、Release 与镜像均指向同一提交。
