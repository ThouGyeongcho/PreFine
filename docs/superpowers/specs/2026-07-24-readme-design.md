# PreFine README 改写设计

日期：2026-07-24

## 目标

将项目根目录的 `README.md` 重写为面向中文使用者的项目说明。参考
`Obsidian-copilot/github-release/README.md` 的表达方式，先说明项目价值和核心能力，
再提供可直接执行的安装、部署与维护步骤。

## 表达原则

- 说明文字全部使用中文，不保留独立的英文介绍或英文运维段落。
- `PreFine`、`Docker`、`GitHub Container Registry`、环境变量、文件名和命令等专有名称保持原样。
- 用短段落、步骤和重点提示组织内容，不堆叠实现细节。
- 只描述仓库当前已经提供的功能和部署方式，不承诺未实现能力。

## 信息结构

1. 项目名称与一句话定位。
2. 项目简介，说明适用对象、私有化部署和单管理员运行方式。
3. 核心亮点，突出金额转换、税收日历、个性化清单、缓存容错和邮件提醒。
4. Docker 部署，依次说明环境要求、获取项目、配置凭据、拉取镜像、启动和访问。
5. 部署配置，说明必填凭据、可选邮件设置、数据目录、端口、版本固定和反向代理要求。
6. 升级与常用运维命令，链接到现有运行手册。
7. 本地开发与测试命令。
8. 相关文档、许可证和安全问题报告入口。

## 部署内容边界

- 明确镜像由 GitHub Actions 构建，使用者只需拉取已发布镜像。
- 使用仓库现有的 `.env.example` 和 `docker-compose.yml`，不在 README 中重复粘贴完整 Compose 文件。
- 给出 Linux/macOS 与 Windows PowerShell 的环境文件复制命令。
- 强调必须修改管理员密码和至少 32 个随机字符的会话密钥。
- 说明默认访问地址、健康检查地址、数据持久化目录和固定版本方法。
- 邮件提醒作为可选配置单独说明；未配置时不影响核心功能。
- 保留反向代理的安全约束，并改写为简洁中文。

## 验收标准

- README 中不存在成段英文说明，代码、命令和专有名称除外。
- 读者能够仅按 README 完成首次部署、健康检查、版本固定和升级。
- 项目用途与五项核心能力出现在部署细节之前。
- 不重复展示仓库中已有的完整 Compose 文件。
- README 中的命令、环境变量、链接与仓库现状一致。
